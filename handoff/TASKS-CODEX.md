## S1. Body-size cap for chunked JSON (Codex R8 row 10)
`server/api.py` `limit_body_size` only checks the declared Content-Length, so a chunked JSON body without Content-Length bypasses the 1 MB cap on `/order`, `/lab/book` and every JSON route. Replace it with a pure ASGI middleware that counts the bytes actually received (wrap `receive`; over the limit -> 413 `{"detail":"request body too large"}` if no response has started) while keeping: the 1 MB default, the 2,000,000 (+16 KB framing) limit for `PHOTO_PATHS` (`/read`, `/judge/scan/read`), the early 413 on an oversized declared length, and the 411 for a photo upload with no Content-Length. Tests: chunked 2 MB JSON to `/order` and `/lab/book` -> 413 (use httpx streaming/`transfer-encoding: chunked`), a normal order still works, photo routes unchanged.
