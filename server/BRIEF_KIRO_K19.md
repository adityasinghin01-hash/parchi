# Kiro task K19: the "last option" reader: a small service that reads the prescription photo with the Claude API
You are the hands; Claude (instructor) and the user re-run everything. Do NOT git commit. Why: our own trained reader is not working yet. A frontier model reading the photo cold scored 82.1% medicine recall / 87.3% precision on 16 real handwritten records (docs/research/01-phase1-reading-the-prescription.md), so the demo's safety net is: the phone blurs what it can, sends the JPEG to our server, the server asks Claude to read it. The server already forwards `POST /read` to `PARCHI_READER_URL` (see `server/api.py` /read, `docs/team/READER-CONTRACT.md`). You build the service behind that URL. NO API key exists yet: everything must be built and tested with a fake client; the user adds the key later.
Other agents are working only in `app/` and `docs/`; `server/` is yours. Never rsync `server/.venv` or `server/data` (use the usual excludes).
## Build (all new files in `server/` unless said)
1. `reader_claude.py`: FastAPI app, run with uvicorn on **127.0.0.1:8100 only**. `POST /read` takes multipart field `image` (jpeg/png/heic, max 2,000,000 bytes) and returns EXACTLY the contract: `{"lines":[{"kind":"medicine"|"test","name":str,"strength"?:str,"quantity"?:int,"schedule"?:str}]}`. `GET /health` -> `{"ok":true,"keyConfigured":bool,"model":str}`. `GET /usage` -> cumulative calls, input/output tokens and estimated cost in USD and INR (INR = USD x 88, say so) since start, no content.
2. Anthropic SDK (`pip install anthropic` into the iMac `server/.venv`, add it to `requirements.txt`). Call: `client.messages.create(model=os.environ.get("PARCHI_READER_MODEL","claude-opus-5-5"), max_tokens=4000, output_config={"effort":"low","format":{"type":"json_schema","schema":<the lines schema, additionalProperties false, required fields>}}, messages=[{"role":"user","content":[{"type":"image","source":{"type":"base64","media_type":<jpeg/png>,"data":b64}},{"type":"text","text":PROMPT}]}])`. Rules for these models: do NOT send `temperature`/`top_p`/`top_k`, do NOT send `thinking: disabled` or `budget_tokens`, no assistant prefill, no forced `tool_choice`. Model IDs are exact strings (`claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`), no date suffix. Price table for the usage endpoint ($ per million tokens in/out): opus-5-5 4/20, sonnet-5-5 2/10, haiku-5-5 0.10/0.50. Read the JSON from the first text block; check `stop_reason`: `refusal` or `max_tokens` -> answer 502 with `{"detail":"reader could not read this photo"}`, never partial output.
3. PROMPT (put it in one constant, English): you are reading ONE photo of an Indian doctor's prescription. Return only what is WRITTEN, in page order: every medicine (kind "medicine", name = the brand or drug name exactly as written, strength = digits+unit as written e.g. "40" or "500 mg", quantity only if a number of tablets/units/days-times-doses is written, schedule only if written e.g. "1-0-1" or "OD/BD"), and every lab test (kind "test", name as written). NEVER guess, expand, correct, or substitute a brand; if a word is unreadable leave that line out; never invent a medicine; do not add generic names; ignore the clinic letterhead, doctor's name and registration, and NEVER output the patient's name, age, phone or address even if visible; if the photo is not a prescription or nothing is readable return an empty list.
4. Output hygiene (pure function, unit-tested): trim, drop empty names, cap 30 lines, `quantity` int 1..10000 else omit, strip control characters, max 80 chars per name; unknown kind -> "medicine".
5. Key handling: `ANTHROPIC_API_KEY` env, else the first line of the file `server/data/anthropic.key` (the user creates it with mode 600). Never log, print, return or store the key, the image bytes or the model's text. No key -> `POST /read` answers **503 `{"detail":"reader not connected"}`** (the app already falls back on that). The image lives only in memory.
6. Errors: 20 s connect / 60 s total timeout; on 429/5xx/connection errors retry ONCE after 1 s, then 502; bad content type 415; too big 413. Use the SDK's typed exceptions (RateLimitError, APIStatusError, APIConnectionError), most specific first.
7. `start_reader.sh` (idempotent like `start_all.sh`; logs to `data/reader.log` without content) and a hook in `start_all.sh` / `stop.sh`: start the reader only if a key exists, and export `PARCHI_READER_URL=http://127.0.0.1:8100/read` for the API process only in that case. Document in `server/README.md` (5 lines: how to add the key, how to switch model, how to stop spending).
8. `eval_reader_claude.py --images <dir> --labels <labels.json> --limit N --yes-spend`: sends MIRAGE images through the running service and scores them with the repo's own scorer (`ai/score_rx.py`; read it and reuse its matching, do not invent new rules). It REFUSES to run more than 5 images unless `--yes-spend` is given, prints the estimated cost in INR before starting and the real cost after (from /usage), and writes `results.json` with recall, precision, blank-page false medicines, s/image. MIRAGE-100 images: the answer key is `docs/research/evidence/labels.json`; the images are on the MacBook at `~/dev/parchi-research/data/mirage100/img` (test only: copy to `~/parchi-data/mirage100` on the iMac, never into the repo).
