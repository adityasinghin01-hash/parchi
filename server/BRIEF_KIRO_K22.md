## Build
1. `GET /judge/scan?k=<admin key>` (same key rule as the existing judge page; wrong key -> 401): a single mobile-first page, big touch targets (min 48 px), works in Chrome on Android and Safari on iPhone, no external requests. Contents: a short warning "TEST PAGE: use test parchis only. This page does NOT hide the patient's name (the app does)."; a file input `accept="image/*" capture="environment"` (opens the rear camera) and a second input without `capture` (choose from gallery); a preview of the chosen image; client-side downscale with a `<canvas>` to at most 2,000 px on the long side and JPEG quality 0.7 (the same limits as the app: up to 2 MB); a "Read this parchi" button.
2. `POST /judge/scan/read` (admin key in the `X-Admin-Key` header, which the page's JS sends from the `k` it was opened with): takes the multipart `image`, forwards it to the reader exactly as `/read` does (`PARCHI_READER_URL`), answers the reader's `{"lines":[...]}` plus `{"ms": <total ms>, "reader": "<host:port only>"}`. Reader missing -> 503 `{"detail":"reader not connected"}` and the page says it in plain words ("The reader is not connected yet"). Never log or store the image or the lines.
3. The page shows the lines as a table (kind, name, strength, quantity, schedule), the time in seconds, "Nothing was found" for an empty list, and the exact error text for failures, with a "Try another photo" button. Names from the reader are inserted with `textContent` (never innerHTML).
4. Document at the top of `server/README.md` (4 lines): how to open it on a phone: `http://<iMac LAN IP>:8000/judge/scan?k=<admin key>` (get the IP with `ipconfig getifaddr en0` / `en1`; the phone must be on the same Wi-Fi; the key is in the URL so do not screenshot the address bar).
