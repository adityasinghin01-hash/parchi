## What the product does (context)
iPhone app builds a plan: items bought from several sellers (local chemist, Jan Aushadhi, quick-commerce, online pharmacy, lab). After the user approves, the order is tracked here. When a seller fails (cancelled, out of stock, late, lab sample rejected) only the failed seller's items are re-routed ("Plan B") after the user approves. The planner (re-routing maths) lives in the phone (Swift `ParchiCore`); this server must NOT re-plan. The server is the durable state machine + audit log; the phone computes the Plan B proposal and posts it back.
Money = integer paise everywhere. JSON keys camelCase as below (they mirror the Swift models):
- PlanLine `{itemID, sellerID, price, isSubstitute}`; Plan `{lines:[PlanLine], feesBySeller:{sellerID:paise}, itemsTotal, feesTotal, stops, maxEtaMinutes, medicinesReadyMinutes, reportsReadyMinutes}`.
- Seller `{id, name, channel(localChemist|janAushadhi|quickCommerce|onlinePharmacy|lab), etaMinutes, requiresVisit, ...}`.
- PlanBProposal `{failure(cancelled|outOfStock|late|sampleRejected), failedSellerID, kept:[PlanLine], rerouted:[PlanLine], newPlan:Plan, extraCost, stillMissing:[itemID]}`.

## Workflow `OrderWorkflow` (Temporal Python SDK, deterministic; id = `order-<order_id>`, task queue `parchi`)
Input `{order_id, install_id, plan, sellers:[Seller], auto_approve_cap_paise|null}`.
State: `plan_version` (starts 1), per-seller status `placed|confirmed|shipped|delivered|failed|rerouted|cancelled`, `state` = `placed|needs_proposal|awaiting_approval|done`, `pending` (current failure `{sellerID,failure}` or null), `proposal`, `queue` (further failures, FIFO, one handled at a time), `needs_check` list, `waiting_since`.
- On start: activity `place_order(order_id, seller_id, plan_version)` for each seller in the plan (parallel). SAFETY: unique key (order_id, seller_id, plan_version) in table `placements`; second call returns the existing row and does NOT create another (this is the no-double-order rule). Audit every step.
- Timers per seller (minutes, scaled by env `PARCHI_TIME_SCALE`, default 1 for the activity-free workflow constant, read via workflow input field `time_scale` so it stays deterministic): (a) confirmation check at +15 min: if the seller is still `placed` (no `confirmed`) -> add seller to `needs_check`, audit "unconfirmed", do not fail. (b) lateness at `seller.etaMinutes + 30`: if not `delivered` -> treat as failure `late`. Lab sellers: the same.
- Signals: `seller_event(seller_id, kind)` kind in `confirmed|shipped|delivered|cancelled|outOfStock|late|sampleRejected` (the last four are failures); `proposal(plan_version, proposal)` (from phone); `approve(plan_version)`; `reject(plan_version)`. Ignore + audit signals for unknown sellers, sellers already `failed/rerouted/cancelled`, and stale `plan_version` (never apply a stale approval; this is a tested rule).
- Failure handling: set seller `failed`, state `needs_proposal`, `pending`=that failure. Wait for `proposal` with the current plan_version (no timeout; record `waiting_since`). If `proposal.rerouted` is empty (stillMissing) -> state `awaiting_approval` with a flag `nothing_available:true` (user sees it plainly; approve just closes it). Else if `auto_approve_cap_paise` is set and `proposal.extraCost <= cap` -> auto-approve with approver `auto-cap`. Otherwise state `awaiting_approval`, wait for approve/reject.
- Approve: plan_version += 1, store the approved plan, failed seller -> `rerouted`, for each seller in `proposal.rerouted` not already placed call `place_order` with the NEW plan_version, seller status `placed`, restart that seller's timers. Reject: failed seller -> `cancelled`, plan unchanged, audit. Then take the next queued failure, else state back to `placed`; when every seller is `delivered|cancelled|rerouted(with replacement delivered)` -> `done`. (Keep this simple and clearly commented; correctness over cleverness.)
- Query `snapshot` returns everything the app needs (see /status). Workflow must survive worker restarts (all state in history; no wall-clock or random in workflow code; use `workflow.now()` / timers).

## API (`api.py`, FastAPI, run: uvicorn on 0.0.0.0:8000)
Auth (`auth.py`): header `X-Install-Key` for app endpoints; keys stored as sha256 in table `keys` (install_id, key_hash, label, created); compare with `hmac.compare_digest`. CLI `python -m auth issue <label>` prints a new key ONCE. Admin key from env `PARCHI_ADMIN_KEY` for judge/reset-all. Rate limit: 60 requests/min per key (sliding window in memory) -> 429 with `Retry-After`. Never log keys.
- `GET /health` (no auth) -> `{ok, temporal:bool}`.
- `POST /order` (install key; header `Idempotency-Key` required): body `{plan, sellers, autoApproveCapPaise?}`; start workflow; same Idempotency-Key returns the SAME order (workflow id derived from install_id + key; handle WorkflowAlreadyStartedError) with 200, new -> 201 `{orderID}`. Validate: prices are ints >= 0, every plan line's seller exists in `sellers`, <= 40 lines.
- `GET /status/{order_id}` (install key, must own the order): `{orderID, state, planVersion, sellers:[{id,status,etaMinutes}], pending, proposal, nothingAvailable, needsCheck:[sellerID], waitingSince, audit:[last 20 rows]}`.
- `POST /order/{order_id}/proposal` `{planVersion, proposal}`, `POST /order/{order_id}/approve` `{planVersion}`, `POST /order/{order_id}/reject` `{planVersion}`: signal the workflow; 409 if planVersion != current.
- `POST /judge/{order_id}/event` `{sellerID, kind}` (admin key in header `X-Admin-Key`): signal `seller_event`. `GET /judge` = one small HTML page (admin key via `?k=`), lists orders (last 20) with per-seller buttons Confirm/Ship/Deliver/Cancel/Out of stock/Late; buttons call the endpoint above with fetch(). Plain HTML+JS, no CDN.
- `POST /reset` (install key) body `{}`: terminate running workflows of that install, delete that install's orders/placements/audit rows (privacy: "delete everything" also clears the server). `POST /reset?scope=demo` (admin key) deletes all orders/placements/audit.
- `POST /read`, `POST /shop/{id}`, `POST /lab/{id}`: return 501 `{"detail":"not built yet"}` for now (reader = Singhal's model, shop/lab = next step). Add a test that asserts 501 so nobody mistakes them for done.
